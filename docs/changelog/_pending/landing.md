## What changed

- **Real video-on-scroll from the live demo.** New `scripts/frames.mjs` builds `dist/` if needed, serves it, and for
  each seeded prospect walks a scripted tour of their own OS demo at 390x844 with dev mode off - role home, two other
  roles, departments, comms, money, life, with small scroll steps at each stop - capturing 24 JPEG frames to
  `public/frames/<prospectId>/NN.jpg`, plus a 12-frame 1280x800 desktop tour (`desk-NN.jpg`) and an `index.json`
  (count, sizes, roles, per-frame tour labels). Role slugs are read from the role switcher the demo itself renders, and
  ids and slugs from the seeded database in the running app, so nothing here is a hard-coded list. Output today:
  **114 files, 4.44 MB** (phone ~36 KB, desktop ~55 KB a frame). Every context runs with `reducedMotion: 'reduce'` so
  the frames are deterministic rather than caught mid-animation.
- **The hero plays them.** `useFrames(prospectId)` fetches `index.json` once per prospect, preloads the first frames
  before showing anything and warms the rest, and returns `null` when there is no sequence. `HeroReveal` puts the phone
  sequence in the phone, the desktop sequence in the laptop, and keeps the live `<MiniOs>` composition in the TV; with
  no sequence all three are `<MiniOs>`, exactly as in pass 1. `WalkthroughSteps` maps its active step onto the desktop
  sequence, so prev / next and the keyboard move the film as well as the scroll.
- **`useScrollFrames` fixed to map the section.** It now returns `scrub` alongside `progress`: `progress` is the old
  enter-to-leave mapping (still what the CSS reveal uses, so the devices are visible on first paint), and `scrub` is
  `-top / (height - viewport)` for a section taller than the viewport - frame 0 on arrival, the last frame on the way
  out. Reduced motion pins `progress` open and `scrub` to 0, so the first frame is the poster and nothing moves.
- **A/B variant selection.** `usePageModel` reads **every** `pages` row for the slug, keeps the live ones, and
  `pickPageVariant()` chooses with `hash(sessionId() + slug) % candidates` over a list sorted by variant then id.
  Stable across reloads in a session, spread across visitors (measured 5 / 5 over ten fresh sessions with two live
  rows), no cookie. `?variant=A|B` forces one, in the hash query or a plain query string. The page root carries
  `data-variant`, and `{ variant, page_id, archetype, slug, variants, variant_forced }` is merged into the meta of
  every event the page emits - `view`, `section_view`, `scroll_depth`, `cta_click`, `demo_open`, `booking_started`,
  `exit_intent`, `form_submit` - through `ctx.track` / `ctx.trackOnce` rather than each section remembering.
- **`/p/:slug` follows the published archetype.** The bare path has no archetype in it, so the chosen row decides;
  `/audit`, `/story` and `/letter` still force theirs over the snapshot. Without this a variant B published as an
  audit would render as a reveal and the test would measure nothing. Proposed decision below.
- **Per-page meta and a social card.** `usePageMeta()` sets `document.title`
  ("&lt;Business&gt;'s operating system, already built"), `meta[name=description]`, `og:title/description/type/url/image`
  and the `twitter:*` pair per prospect **and language**, restoring what was there on unmount. New hidden route
  **L-06 `/og/:slug`** renders a 1200x630 branded card - business, city, the headline from the published `PageModel`,
  the palette as swatches, and phone / laptop / TV mockups - and `scripts/og.mjs` screenshots the `.og-card` element to
  `public/og/<slug>.jpg` (three cards, 88-103 KB). The card scales with `min(1, (100vw - 32px) / 1200)` so the route is
  phone-safe, and `og.mjs` opens a 1240x760 viewport where the scale is exactly 1.
- **Conversion polish.**
  - *Hero:* the two strongest personal facts under the subline - `{city} · a team of {n}` (with locations when there is
    more than one) and the top pain from the industry catalog, each with an icon.
  - *Savings:* rows cross themselves out one every ~85-150 ms (the whole list inside ~1.1 s) with a **running total in
    text** under the list - "Cancelled so far: $769 a month" plus "10 of 13 tools crossed off", `aria-live="polite"`,
    tabular numerals - so the subtraction never depends on seeing a coloured line.
  - *Roles:* every card ends in "Try it as &lt;role&gt;", opening `/demo/:id/role/:slug` with the role slug computed the
    same way the demo does (a colliding life role becomes `life-<slug>`), tracked as `cta_click` +`demo_open` with the
    role in the meta. New action `landing.tryAsRole`.
  - *Proof:* the sample block is headed "Sample, not a customer" and the logo strip is named as placeholder marks.
  - *Sticky CTA (phone):* "Save $3,848 a year" above the buttons, from the same live savings the stack shows.
  - *Exit intent:* six real slots from `src/engine/slots.ts` inside the modal - the calendar itself, not a link to it
    (R-C02) - each one deep-linking B-01 with that slot.
- **4K band.** A `@media (min-width: 3840px)` block gives the headline, lede, facts, stack rows and running total
  explicit 10-foot sizes (headline up to 176 px, lede 46 px, facts 42 px, running total 68 px) and widens `.lp-wrap` to
  3200 px so the hero is not a stamp in the middle of the wall.

## New and changed contracts

- `useScrollFrames(count)` -> `{ ref, frame, frames, progress, scrub, reduced }`. **`scrub` is new and `frame` now
  derives from it** (it used to derive from `progress`). Anything that wants the old reveal behaviour reads `progress`.
- `useFrames(prospectId)` -> `FrameSet | null` = `{ phone: string[], desk: string[], labels, deskLabels, index }`,
  module-cached and preloaded. `assetBase()` resolves `public/` files under Vite's `./` base and a hash route.
- `usePageMeta(meta)` and `pageMetaFor(prospect, lang, annual, toolsCut)` in `src/modules/landing/useMeta.ts`;
  `publicUrl(path)` returns an absolute URL for `og:image`.
- `usePageModel(slug, archetype, followRow?)` now returns `variants: PageRow[]` and `forced: boolean` on the live
  state. Exported: `pickPageVariant(rows, visitorKey, forced?)`, `hashString(s)`, `useForcedVariant()`.
- `LandingCtx` gained `savings`, `variants`, `eventMeta`, `track(type, meta?)`, `trackOnce(key, type, meta?)` and
  `openRole(from, view, all?)`. Sections now track through the context, never through `src/tracking` directly.
- `src/modules/landing/format.ts` exports `roleSlug` and `viewSlug`, mirroring `src/modules/os-demo/people.ts` so the
  two modules stay independent. **If the demo ever changes its slug rule, this is the second place to change.**
- Two npm scripts: `npm run frames`, `npm run og`. Both take `--port=`, `--quality=`, and a subset filter
  (`--ids=`, `--slugs=`); both build `dist/` first if it is missing and use the preinstalled Chromium.
- New static content: `public/frames/<prospectId>/{NN.jpg, desk-NN.jpg, index.json}` and `public/og/<slug>.jpg`.

## Proposed decisions

- **D-0xx (proposed): video-on-scroll is screenshots of the running product, committed as static files.**
  `npm run frames` walks the real demo and commits the JPEG sequence; pages degrade to the live composition when it is
  absent. Rejected: generated / AI video (T40 is not wired and a rendered fake of a product that exists is the one
  dishonest thing we could put above the fold), a `<video>` element (a JPEG sequence scrubs, seeks and respects
  reduced motion with no extra code), and generating in CI (product screenshots should change in a reviewable commit).
  Cost: ~4.4 MB in the repo and a regeneration step whenever the demo's look changes.
- **D-0xx (proposed): the A/B bucket is `hash(sessionId() + slug) % live rows`.** Deterministic per visitor, spread
  across visitors, no cookie, no server. Rejected: random per view (uncomparable events, page changes under the
  visitor) and a stored flag (nothing to serve from yet).
- **D-0xx (proposed): `/p/:slug` renders the archetype the published row carries; the explicit paths force theirs.**
  This is a refinement of the pass-1 decision that "the archetype in the URL wins over the snapshot" - the bare path
  has no archetype in it. Without it, a variant B published as an audit renders as a reveal and the test is void.
- **D-0xx (proposed): static prerender of `/p/<slug>` at build time (a later task).** A HashRouter route cannot give a
  crawler that does not run JavaScript per-page `og:` tags, so today every prospect link unfurls with `index.html`'s
  tags. Prerendering each live slug to a real HTML file (with its title, description and `og:image` baked in, the SPA
  taking over on load) fixes it. Alternative rejected: switching to `BrowserRouter` (GitHub Pages has no rewrite rule,
  so every deep link would 404).
