### Accessibility, from the scan to zero (T32)
Sonnet 5's first run (dev server, before any fix): **2034 axe instances (all serious), 87 focus failures, 775 hit-target failures**. Final run on the v0.3.0 build, 51 routes x 390 / 1280: **0 / 0 / 0**.

Prospect surfaces: `--lp-on-primary` / `--lp-on-accent` computed (`readableOn`), `--lp-muted` 72 %, `--lp-primary-text` 70 % mix for small primary-coloured copy (landing link buttons, eyebrows, badges, sticky total, proposal phases and signature, website preview, demo mapping 76 / 72 / 68 % and 64 % primary-text, `Avatar` initials by contrast). The L-03 / S-03 mini-OS text was being measured mid-fade at ~5 % opacity: devices now fade from exactly 0 with a steeper ramp. D-07 thumbnail codes, D-02 sidebar codes inside the active link, S-03 links, W-01 preview.
- `link-in-text-block` (7 -> 0): links inside running text are underlined (`:where(p, li, td, dd, figcaption, small, .small, .xs, .muted, .prose) a:not([class])`).
- `scrollable-region-focusable` (7 -> 0): `.dw-week`, the S-02 transcript, the W-02 diagram card (`role="region"` + label) and K-03's scroller are `tabIndex=0`; the `ErrorBoundary` message wraps instead of scrolling.

- Focus (87 -> 0): the plan graph nodes carry a real `outline` on `:focus-visible` (plus the thicker box stroke); the 67 iframe failures were the checker's: Chromium never matches `iframe:focus`, so `qa-a11y.mjs` now reads the ring on the element focused inside a same-origin frame.
