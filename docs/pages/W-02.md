# W-02 · How it works

## Purpose

The method in plain words, for a visitor who wants to know how a system can already exist before they talk to anyone: intake, stack guess, compose, demo, book, adapt. Includes the engine diagram, the questions people actually ask, and - in dev mode only - an honest list of what the product does not wire yet.

## Logic

- The six steps mirror the engine functions (`nextQuestions` -> `guessStack` -> `composePage` -> demo -> booking -> `adaptFromEvents`), so the marketing copy cannot drift from the code.
- The diagram is inline SVG with `role="img"`, a `<title>` and a `<desc>` (the same six steps in words), and scrolls horizontally on a phone rather than shrinking below legibility.
- The not-wired list renders only when dev mode is on: honest to the team, not alarming to a visitor; the same gaps are marked as `Placeholder` wherever they appear in the product (P-09).

## Components

SiteChrome, Card, Badge, Button, Icon, LangToggle.

## Real vs mock

The page is copy plus one diagram; nothing is faked. The gaps it lists are the real ones: image generation (T40), LLM enrichment (T43), booking provider (T42), Stripe (T51), Supabase (T44), e-signature (later pass).
