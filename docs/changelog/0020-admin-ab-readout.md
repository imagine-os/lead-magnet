decision: (1) an A/B is exactly two live rows on one slug and is read per slug, never pooled across slugs - pooling variant "A" across different prospects is a Simpson's-paradox trap, so the old global by-variant table is gone; (2) the compared metric is view -> demo_open (the page's own job) with a minimum of 30 view sessions per variant and a 10 % relative lift before any side is called ahead (R-A04), bookings shown but never deciding; (3) both sides are drawn on ONE shared scale in a new `PairedBarChart`, because two self-normalised funnels are the classic A/B misread; (4) a winning side becomes a `recommendations` row (`kind: promote_variant`, `status: proposed`) and promoting is a `Placeholder` by S-03 - nothing on A-01 changes a live page (R-A03 / D-044); (5) the readout ignores the archetype and warmth filters on purpose (variant B is usually a different archetype) and says so on screen; (6) the seed ships two live splits so both honest states - "B ahead" and "not enough data" - are on screen from the first load.
rejected: Declaring a winner from whichever side is higher (a 3-session lead is noise; the threshold exists to make the page refuse); comparing on booking_confirmed (per page it is far too sparse - the rate would swing on one call); two `FunnelChart`s side by side (each normalises to its own maximum, so equal-length bars would imply equal traffic); a stats library / p-values (a dependency plus a claim we cannot back with this traffic - a stated sample gate and a relative lift are honest and legible; a proper significance test is a decision for Justin); auto-writing the recommendation on render (a write should follow a human act, and R-A03 wants the decider recorded); auto-expiring variant A (that is a publish, and publishes live in the composer); depending on the shared `DateRange` molecule or the new `DataTable` sortable headers (both in flight in other workers this pass - A-01 ships a `SegmentedControl` and adopts the molecule next pass).

## What changed

- **A-01 A/B readout (T53).** The old "A/B by variant" table (one pooled row per variant letter across every slug) is replaced by a per-slug readout:
  - a `Select` of the slugs actually running a split, deep-linked as `/#/admin?slug=<slug>` (the URL follows the select and the select follows the URL, `replace: true` so Back is not littered);
  - the two sides as cards side by side - variant, archetype, page status, live since, sessions with "{n} of them viewed the page", view → demo with its two counts, and a link that opens that exact side (`#/p/<slug>?variant=A|B`, the studio's forcing link);
  - one `PairedBarChart`: both funnels, five stages, **one shared scale**, each bar tagged A / B with its value as text;
  - the comparison `DataTable`, always visible: per stage, A sessions, A of-previous **with its counts**, B sessions, B of-previous with its counts, and B − A in percentage points (R-A02: no rate without its counts);
  - a verdict line that states the rule it is applying ("compared on Page viewed → Demo opened, the page's own job · minimum 30 sessions per variant · minimum 10 % relative lift") and, below the sample, says how far off each side is instead of implying a winner.
- **Recommendation hook.** When B is ahead past both gates, a Recommendation block appears: **Record: promote variant B** inserts a `recommendations` row (`kind: promote_variant`, `status: proposed`, `decided_by` the current user, `reason` carrying both rates with their counts and the relative lift, `score` = lift / 10) through the provider, and flips to "On file since …" with the row's status badge. Next to it, **Promote variant B** is a `Placeholder` (will: expire variant A on this slug and serve B to everyone; by: S-03). Nothing here writes to `pages`.
- **A-01 date range.** A 7 / 30 / 90 / all `SegmentedControl` (default 30) now scopes every number on the page, including the A/B readout, with "{shown} of {all} events in range" beside it. It was missing entirely - the page read all events forever.
- **A-03 A/B column and filter.** A `Variant` `Select` (All / A / B) joins the other four filters, and a `Variant` `Badge` column sits beside the page column (which now shows the slug alone); the drawer names the variant too. Resolution is `variantOfEvent()`: the `pages` row the event points at, else the `variant` the landing page stamped into `meta`, else "no page". This is what `track()` actually records - `page_id`, `prospect_id`, `session_id`, `type`, `meta`, `ts` - plus the landing module's `{ variant, page_id, archetype, slug }` base meta. Nothing was invented.
- **Seeded A/B traffic.** `src/data/seed/admin.ts` now publishes variant B beside two of the three seeded pages (a different archetype each, its own `composePage()` snapshot, same slug and publish moment) and writes their sessions as `events` rows exactly as `track()` does: Highline Hospitality (A 41 sessions / B 39; on view → demo B is at 52.8 % (19 / 36) against A's 40.5 % (15 / 37), a 30 % relative lift - both sides past the 30-session gate) and Sonrisa Dental (A 10 / B 8, far below the sample). Maya's slug is left single-variant on purpose: `paws-and-play-austin` is the QA default for `/p/:slug`, and a second live row there would make the landing screenshots flip archetype with the visitor hash. Both honest states are therefore on screen from the first load. These are tracked sessions only - no fabricated `bookings` rows, so A-05 still shows what prospects really booked.
- **New component `PairedBarChart` (molecule)** with meta and a usage - see the contracts section.
- Checked in the browser at 360 / 390 / 768 / 1280 light and dark: no horizontal overflow at any width, the two sides stack under 768, the chart stacks its stage label above the pair under 720, and the six-column comparison table uses `DataTable`'s card mode below 768.

## New and changed contracts

- **New component `PairedBarChart`** (`src/components/molecule/PairedBarChart/`): `{ series: [PairedSeries, PairedSeries], rows: PairedRow[], caption, unitLabel?, tableFallback?, tableLabel? }`. Two series, grouped horizontal bars, **one shared maximum**, 14 px marks with a 4 px rounded data-end and a 2 px surface gap inside the pair, a legend with both series, a series tag and a text value on every bar, and a disclosure slot for a table view. `usedBy: ['A-01']`.
  - Colour: a **two-slot categorical pair**, validated with the dataviz checker in each theme - light on `--color-surface` #FFFFFF: `#4A66F0` (`--electric-600`) vs `#6B9E22` (deutan ΔE 33.3, tritan 10.1, both ≥ 3:1); dark on #161A2B: `#5B7CFF` (`--electric-500`) vs `#71A825` (protan ΔE 32.8, tritan 8.9, both ≥ 3:1). The two greens are **not tokens yet** (see Requests to foundation) and are declared as local custom properties at the top of the component's CSS with the validation numbers in a comment.
- **New module API `src/modules/admin/ab.ts`** (pure): `AB_MIN_SESSIONS` (30), `AB_MIN_LIFT` (0.1), `AB_METRIC` (`view -> demo_open`), `VARIANTS`, `normalizeVariant`, `variantOfEvent(event, pageById)`, `abSlugs(pages)`, `abReadout(slug, pages, events) -> { sides, verdict: 'not_enough' | 'too_close' | 'leader', leader, lift, smallestSample, … }`, `rateWithCounts(to, from)`, `ppDiff(...)`, `stagesOf(counts)`. Everything counts through `./funnel`, so the A/B numbers and the funnel above them cannot disagree.
- **`recommendations.kind` gains `promote_variant`** (`src/data/schema/admin.ts`). `to_archetype` holds the winning side's archetype, `note` the slug. Regenerate `supabase/schema.sql` and `docs/data-model.md` with `npm run sql`. A-02 now skips `promote_variant` rows when it keys recorded recommendations against the engine's four kinds (they have no engine counterpart).
- **Actions.** New on A-01: `admin.compareVariants {slug}` (intent "compare the A/B variants on {slug}", `events.read`) and `admin.recordAbWinner` (intent "record the recommendation to promote the winning variant", `prospects.write` - it writes a row, so it follows A-02's `admin.recordRecommendation` rather than the page's `events.read` filters). Changed: `admin.filterFunnel` gains `range: enum:7|30|90|all`; `admin.filterEvents` (A-03) gains `variant: enum:A|B`. `admin.compareVariants` replies with the slugs that are running a split when it is handed one that is not.
- **New rule `R-A04`** (no winner below the minimum sample) and a rewritten **`R-A02`** (an A/B readout is per slug, needs two live rows, and every rate carries its counts) in `src/rules/admin.ts`.
- **Seed**: `src/data/seed/admin.ts` (order 5) now writes `pages` rows `pg_priya_b` and `pg_daniel_b` and ~280 `events` rows. It reads the variant-A rows out of `ctx.db.pages`, so it can never disagree with what `prospects.ts` published.
