### Engine (T55 + meter)

- `industryFor(p)` (new, `catalog/industries.ts`): the industry with the sub's `departments / kpis / pains / motifs / roles (as business_roles) / meter` in place of its own when the sub gives them; `key, label, verbs, stack, sub, life_roles` stay the industry's; without a sub, or with one that adds nothing, **the very same `Industry` object** comes back (`strictEqual`-checked), which is what keeps the existing pages byte-stable. `subIndustryFor(p)` and `catalogItem(tool)` (first priced item for a tool name across the catalog) are exported beside it.
- `candidateStack(p)` (new, `stack.ts`): the industry stack plus the sub's `extra_tools`; an extra already in the stack takes the sub's prevalence (the sub knows better - Ecwid is 0.1 for law firms, 0.8 for tenant law), one from another industry is pulled in at the sub's prevalence with its catalog price (pet care `grooming` gets Vagaro at $45). `guessStack()` reads it; everything else in `guessStack()` (one per category, one per replacement, confirmed first, rare gate, rejected stays rejected) is untouched.
- `deriveRoleViews()`: reads `industryFor(p)`; for roles matching `/owner|partner|director|manager/` the KPI tile becomes a `meter` widget when `ind.meter` exists (`sample: MeterSample { value, max, unit, hint }`, hint bilingual: "50 of 58 rooms" / "50 de 58 habitaciones"). Still exactly three widgets per view.
- `composePage()`, `imagePrompts()`, `RuleEnricher.enrich()`: read `industryFor(p)`, so the proof section's "Your departments", the letter's first paragraph, the device-mockup prompts and the enricher's default roles follow the sub.
