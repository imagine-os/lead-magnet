# K-04 · Task detail

## Purpose

One task in full: status, model, phase, module, owner, codes, notes, `done_at`, and the dependency graph in both directions - what it waits on and what waits on it, each linked. The status Select is the one place a task can be set to any lane with the rule explained in the field hint.

## Sections (layout order)

1. Head - breadcrumb (Kanban / id), title, links to K-02 / K-03
2. Badges - status, model, phase, ready
3. Status card - status Select with the R-K01 hint, then a facts list (module, owner, model, phase, codes, done at, updated)
4. Notes card - notes plus links to R-K01..R-K04
5. Waits on - upstream dependencies with their status and model
6. Blocks - the tasks that name this one in `depends_on`
7. Footer - "see it in the graph" (focuses this task on K-03), back to the Kanban

## Data

| Table | Read / write | Notes |
| --- | --- | --- |
| `tasks` | read + write | `status` + `done_at` written by id through `useData().update` |

## Actions

| id | intent | permission |
| --- | --- | --- |
| `plan.setStatus` | "set {task} to {status}" | `plan.edit` |
| `plan.openTask` | "open task {task}" | - |

## Rules

- `R-K01` - the field hint says either "every dependency is done, so this can move to done" or names what is still open; the write is refused with a toast.
- `R-K02` - the model is a badge in the header and beside every dependency.
- `R-K03` - the Select offers exactly the five lanes.
- `R-K04` - the ready badge and `done_at` come from `readiness()` / `statusPatch()`.

## Logic

- An unknown id renders an `EmptyState` with a link back to the Kanban (no crash, no blank page).
- Dependencies that are not in the table are listed as "unknown task" rather than silently dropped.
- Without `plan.edit` the Select is replaced by the read-only note.

## Components

Card, Badge, Button, Select, Field, EmptyState.

## Real vs mock

All real. Editing the title, notes, codes or dependencies from the UI is not in this pass - the plan's shape is authored in `docs/build-plan.md` / `src/data/seed/plan.ts` and only `status` moves from the product.
