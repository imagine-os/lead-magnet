# K-01 · Plan Kanban

## Purpose

The development plan as five lanes. A strategist opens `/#/plan` to see what is in flight, what is ready to start and what is waiting on Justin, and moves a task between lanes without leaving the page. Every card names the model that does the work (R-K02), the page codes it ships, how many of its dependencies are done and whether it is ready. Tasks are bound by dependencies, not calendar days, so there is no date anywhere on this page.

## Sections (layout order)

1. Head - title, the "bound by dependencies" line, links to K-02 / K-03
2. Counts - tasks, done, ready, waiting (blocked + awaiting Justin) + progress bar
3. Filters - phase chips, model chips, "ready only" chip, `Sync to build-plan.md` (Placeholder, T20)
4. Lanes - backlog / doing / done / blocked / awaiting Justin, each a `<section>` with its count
5. Cards - id (links to K-04), model badge, phase, title, module, code chips, dependency count + ready badge, move controls

## Rules

- `R-K01` - a move to done is refused while a dependency is open; the toast names the missing task ids.
- `R-K02` - every card shows its model with a distinct Badge tone (Fable 5.1 primary, Opus 5 accent, Sonnet 5 info, Justin warn).
- `R-K03` - the five lanes are `TASK_STATUS`; the Select offers exactly those.
- `R-K04` - ready = every dependency done; the "ready only" filter and the ready badge both read `readiness()`.

## Logic

- `readiness(task, map)` counts done dependencies and returns the missing ids.
- `statusChange()` gates the write (R-K01); `statusPatch()` stamps `done_at` on done and clears it on any move out.
- Prev / next lane buttons step through `LANES`; they are disabled at the ends. The Select is the direct route. Nothing is drag-only (P-03) - there is no drag at all in this pass.
- Without `plan.edit` (analyst) the move controls are not rendered and a status line says so.

## Components

## Real vs mock

Real: every read and write, through the MockProvider (localStorage) - the same calls work against Supabase when T44 lands. Mock: `Sync to build-plan.md` is a Placeholder; docs are written by hand in the same turn as the work (P-11) until T20 automates it.
