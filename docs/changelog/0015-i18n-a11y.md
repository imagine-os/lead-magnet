intent: (i18n) Finish P-08/T30 Spanish fill with a repeatable audit instead of a one-off read-through: a script that lists every string-table key whose `es` is missing or identical to `en`, so the gap is always visible instead of trusted to memory. (a11y) Finish T32 (P-01 accessibility bullets) with a repeatable, automated scan instead of a manual pass: axe-core (WCAG 2.1 AA) plus a keyboard walk (visible focus ring + 44x44 hit target) across every built route, so drift shows up in a report instead of being trusted to memory.
decision: (i18n) (1) `scripts/i18n-check.mjs` bundles each `src/modules/<name>/index.ts` with esbuild the same way `scripts/actions.mjs` bundles routes, because the string tables live inside files that import `.tsx`/`.css` that bare Node can't resolve; (2) a key is only flagged when `es` is missing or byte-identical to `en` **and** `en` is not exempt (URL, email, page code, pure number/percentage, currency band like `$250k - $1M`, a lone `{placeholder}`, a known proper noun, or an all-caps acronym) - a plain-string entry (no `{en, es}` shape) is never flagged, since `I18nProvider` renders those language-neutral; (3) `src/a11y/strings.ts` is read directly (it exports bare `Bi` constants, not a `strings` table) rather than folded into the module loop; (4) `--strict` is the only exit-code lever, so CI can adopt it later without the default `npm run i18n:check` breaking a build today. (a11y) (1) `@axe-core/playwright` over hand-rolled contrast/ARIA checks - it is the maintained reference implementation of the WCAG 2.1 AA ruleset and returns exact selectors and rule ids, which a hand-rolled checker would have to reinvent and would inevitably cover less of; (2) `scripts/qa-a11y.mjs` serves `dist/` with `vite preview` when it exists and falls back to the Vite dev server otherwise (`--server=dev|preview|auto`), because this repo's `dist/` is mid-build and stale right now - `qa-responsive.mjs` always requires a fresh build first, this script does not have that luxury today; (3) the keyboard-walk focus-ring check reads computed `outline`/`box-shadow` only, not rendered pixels or SVG `stroke` - cheap and correct for ordinary DOM controls, but it produces false positives on the one component that signals focus via an SVG attribute instead (see caveat below); (4) violations are grouped per route x width (390/1280) rather than deduplicated across the app, so a shared component's problem is visibly repeated - the "routes hit" column in Top rules is the dedup view.
rejected: (i18n) a static grep over the source text (misses the `{en, es}` object shape and can't tell a plain string from a bilingual one); flagging every `es === en` unconditionally (would permanently flag correct one-word cognates like "idea"/"comparable" and established in-app loanwords like "Outreach"/"Intake"/"Kanban"/"Prompt" that this codebase already translates consistently, drowning the real gaps); shipping the checker with `--strict` wired into `build` (T30 says Spanish fill is a pass, never a blocker - the script is a worker's tool, not a gate, until Justin decides otherwise). (a11y) `jest-axe` / a unit-test harness (the personalization engine means every route needs a real seeded prospect and a real router, which is what the existing QA scripts already set up - duplicating that in a test runner is two ways to boot the app); hand-rolled contrast math (axe already resolves computed colors through opacity/background stacking correctly, which a naive foreground/background luminance calc on two declared colors would get wrong for badges rendered over gradients or overlays).
files: scripts/i18n-check.mjs (new), package.json (`i18n:check` script line only), src/modules/admin/index.ts (`admin.ev_meta` -> "Metadatos"), src/modules/hub/index.ts (`hub.docs` -> "Documentación", `hub.stubs` -> "pendientes"), docs/changelog/_pending/i18n.md; scripts/qa-a11y.mjs (new), package.json (`@axe-core/playwright` devDependency + `qa:a11y` script line only), docs/qa/a11y-report.{md,json} (new), docs/changelog/_pending/a11y.md

# Part II - a11y (T32)

## What changed

- **`scripts/qa-a11y.mjs`** (new) - `npm run qa:a11y [-- --only=/dev] [-- --codes=D-07] [-- --widths=390,1280] [-- --server=dev|preview|auto] [-- --port=N]`. For every **built** manifest route (stubs skipped - nothing to scan): opens it at 390 and 1280 as the super admin with dev mode off and light theme, runs `AxeBuilder(page).withTags(['wcag2a','wcag2aa','wcag21a','wcag21aa']).analyze()`, then tabs through the first 40 focusable elements checking a visible focus indicator and a >=44x44 hit target (skipped for inline text links). Writes `docs/qa/a11y-report.{md,json}` (totals, top rules by node-instance count, a per-route matrix, and per-route finding detail).
- **`@axe-core/playwright` added as a devDependency** (v4.13.0, via the proxy).
- **Ran it once against the dev server** (`--server=dev`; `dist/` is mid-build) across all 51 built routes x 2 widths = 102 cells.

## Top 10 findings for the integrator (file hints, not fixed - per instruction)

1. **`color-contrast` is 2013 of the 2034 axe violations, hit on 35 of 51 routes.** It is not one bug, it is a handful of shared-color pairings reused everywhere:
   - **Badge tones** (`badge-warn`, `badge-info`, `badge-success`, `badge-danger`) - `src/components/atom/Badge/Badge.css:3-9`, tokens in `src/design/tokens.ts:124` (`color-warn`/`color-warn-bg` etc.). Drives most of the `S-02`/`S-03`/`K-0x`/`D-05`/`A-03` counts (badges appear in tables and cards everywhere).
   - **`.eyebrow`** (uppercase micro-label) - `src/styles/global.css:48`, `color: var(--color-text-faint)`. Hits almost every card-based page (`S-0x`, `K-0x`, `D-0x`).
   - **Landing footer text** (`.lp-foot-in`, `.lp-foot-meta`, `.lp-linkbtn`) - `src/modules/landing/landing.css:49` and around. Hits every `L-0x` route and (via the same-origin preview iframe, see #10) `S-03`.
   - **Demo calendar small text** (`.dw-ev-who.xs`) and **`Stat` label** (`.stat-label`) - `src/modules/os-demo/demo.css` (widgets), `src/components/molecule/Stat/Stat.css`.
2. **`.langtoggle-btn` (EN/ES toggle) renders 44x40, not the 44x44 its own CSS declares.** `src/components/molecule/LangToggle/LangToggle.css:2` sets `min-height: 44px` on `.langtoggle-btn`, and the wrapper `.langtoggle` (`display: inline-flex`, line 1) has no explicit `align-items`, so children should stretch to the tallest sibling - but the keyboard walk measures 40px on every route it appears on (nearly all of them, `size="sm"` usage in `TopBar.tsx:20`, `LandingPage.tsx:160`, `ExpiredPage.tsx:65`, `DemoShell.tsx:137`). Worth a manual look at what's clamping it to 40 (a parent height, a line-height reset, or box-sizing) rather than assuming the CSS as written is what's shipping. Single fix, ~30+ occurrences.
3. **`a.demo-skip` "Skip to content" is 133x39**, under the 44px floor, on every `C-0x` demo route - `src/modules/os-demo/DemoShell.tsx` / `src/modules/os-demo/demo.css` (`.demo-skip`).
4. **67 of the 87 focus-ring failures are the compose page's live preview `<iframe>`s** (`S-03`, `src/modules/studio/ComposePage.tsx`, likely via `src/components/molecule/ViewportFrame/ViewportFrame.tsx`). Verified directly (not just from the report): a manual Tab through `/#/studio/prospects/pro_maya/compose` lands on these iframes with `outlineStyle: none`, `outlineWidth: 0px`, `boxShadow: none`, no class on the `<iframe>` itself - so the app's global `:focus-visible { outline: ... }` rule (`src/styles/global.css:22`) is not reaching it. `ViewportFrame.css`/`PhoneFrame.css` set `border: 0` on the iframe but no outline reset, so the cause isn't obvious from the CSS alone; worth a focused look rather than a guess.
5. **`nested-interactive` on `.pl-graph`** (`K-03` plan timeline, `src/modules/plan/TimelinePage.tsx`) - an interactive control inside another interactive control; axe reports 1 instance per width. Likely the SVG node group (`role="button"`, line ~131) has an interactive child (e.g. a nested `<a>` or button) that should be a sibling instead.
6. **`scrollable-region-focusable`**: `.dw-week` (demo calendar, `src/modules/os-demo/widgets.tsx`) and plain `ol` elements (`K-0x`, `D-07`) scroll but have no `tabindex`/keyboard access - a P-01 gap (keyboard input, not just screen readers).
7. **`aria-prohibited-attr` on `.lp-logos`** (`L-01`..`L-04`, `src/modules/landing/sections/Proof.tsx`) - an ARIA attribute on an element type that doesn't accept it; likely a stray `aria-*` on a `<ul>`/`<div>` that should either move to a child or be dropped.
8. **`link-in-text-block`** on `a[href$="#/site"]` (`L-05` expired page body copy, `src/modules/landing/ExpiredPage.tsx`) - an inline link relies on color alone; needs an underline or weight change so it reads as a link without color.
9. **20 of the 87 focus-ring failures are SVG `g.pl-node` elements in the plan dependency graph (`K-01`/`K-03`, `D-07`) - likely a false positive of this checker, not a real gap.** `src/modules/plan/plan.css:66` already sets `.pl-node:focus-visible .pl-node-box { stroke: var(--color-focus); stroke-width: 3; }` - a real, deliberate focus indicator, just expressed as an SVG `stroke` change on a child element rather than `outline`/`box-shadow` on the focused element itself, which is all this checker's heuristic reads. **Do not "fix" this from the report alone** - `qa-a11y.mjs`'s keyboard-walk needs a follow-up pass (screenshot diff, or read the child's `stroke`/`fill` too) before its focus-ring number can be trusted for SVG-based controls. Left as a known limitation rather than silently special-cased, so it doesn't hide a real future gap in a different SVG component.
10. **`S-03`'s 317 findings are inflated by its own layout, not a studio-specific defect**: the compose page previews the real public landing route live inside 4 archetype `iframe`s (D-029 - "S-03 never renders landing sections itself"), so most of its `color-contrast`/`aria-prohibited-attr` hits (e.g. `iframe[title="Phone..."] .lp-logos`) are **the same landing-page findings as #1 and #7**, counted once per preview. The integrator should fix the landing-page source (item 1/7) rather than anything in `ComposePage.tsx`.
