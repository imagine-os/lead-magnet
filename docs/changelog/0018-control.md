# control - Voice controller + command palette (T46), spatial navigation on every shell + d-pad rehearsal (T47)

version: 0.4.0
date: 2026-09-19
prompt: 0004
intent: Give the actions manifest its voice: a pure phrase matcher over the generated vocabulary (EN + ES, slot extraction), a Web Speech hook that never listens without a gesture, and one CommandPalette (Ctrl/Cmd+K + visible 44 px buttons in the TopBar and on the hub) that lists, gates and runs any action through `runAction`. Finish P-04 groundwork: `useSpatialNav` + `useGamepadNav` on `DesktopShell`, Escape parks focus inside arrow-owning controls, and `npm run qa:dpad` rehearses every built route with arrow keys only.
decision: (1) matching is a canonicalisation + ordered template alignment, not fuzzy string distance and not an LLM: the intents are short imperative templates, so folding ES / synonyms onto their wording and aligning literals in order gives deterministic, testable, offline ranking with slot spans for free (proposed D-099); (2) the microphone starts only inside a user gesture (`navigator.userActivation.isActive`), never on mount, open, route change or from a bus call - `hub.voiceListen` from the CLI opens the palette and focuses the mic instead (proposed D-100); (3) the palette IS the voice screen: what is heard lands in the same input, ranked the same way, run the same way, so voice has no second UI to keep in sync and a confident match (>= 0.8, slots filled, 0.15 ahead) runs at once while anything ambiguous shows the list (proposed D-101); (4) spatial navigation scope on staff pages is the whole `DesktopShell` (sidebar + top bar + content as one grid) rather than the content region alone, so Left from the content reaches the sidebar and a remote never needs Tab; Escape inside a select / text field parks focus so the next arrow continues (proposed D-102); (5) `control.*` strings live in the hub module table (D-092: no strings outside module tables; the hub declares the palette's actions).
rejected: Levenshtein / fuzzy string matching over whole phrases (word order and Spanish break it, no slot values); an LLM intent classifier (offline, deterministic and unit-checkable beats it for 144 short templates; an enricher can sit in front later); a separate "voice screen" or overlay (would duplicate the list, the gating and the run path); auto-listen when the palette opens (violates "never auto-listen"; browsers also gate it); mounting `useSpatialNav` on `.shell-content` only (a d-pad could never reach the sidebar without Tab; the rehearsal counted that as unreachable); `provideContext` for the palette (same reasons as D-064); a `mic` icon in `Icon.tsx` (atom folder belongs to the components worker this pass - inline SVG inside the organism, request below); a new `src/modules/control` strings module (an index without routes is legal but a module folder for six words is noise; hub already owns the actions).

## What changed
- **`matchPhrase`** (`src/a11y/voice.ts`): normalise -> multi-word rewrites (`modo oscuro` -> `dark mode`, `go to` / `ir a` -> `open`, `turn on` / `activar` -> `on`, `base de datos` -> `database`, ...) -> per-token canon (ES -> EN dictionary of ~400 forms incl. conjugations, EN synonyms, light stem; ids and numbers pass through with their case) -> ordered template alignment (literals in order, stopwords free, tokens between two literals fill the slot between them) -> typed slots (`number` digits or EN / ES number words; `enum` value or its ES word, `hecha` -> `done`; `id` id-shaped token, else an id from the current route when the speaker says "this / esta" or names none; `string` quoted span first) -> score `0.55 coverage + 0.15 precision + 0.15 bigram similarity + 0.15 slot fill (+0.15 on page, +0.05 live)`, threshold 0.45. `npm run test:voice`: 18 checks (EN, ES, enum / number / id / quoted / route slots, page and live bonuses, tie-break by page, nonsense -> [], limit / threshold, the two new hub actions).
- **`useVoice`** (`src/a11y/useVoice.ts`): Web Speech feature-detected; states `idle | listening | unsupported | denied`; `start()` refuses without transient user activation; one utterance per start, interim results, `en-US` / `es-US`; nothing listens on mount.
- **`CommandPalette`** organism + `src/actions/palette.ts` store; mounted once by `ControlBridge` -> available on every shell (landing and demo included; only the staff shell and the hub have a visible button today, landing / demo keep their chrome). Combobox input with `aria-activedescendant`, 56 px option rows (64 px at >= 1920) with label, filled phrase, page, live / opens-page and permission badges; `can(permission)` hides what the role cannot run and counts it; params form from the JSON Schema prefilled from the phrase; Enter / click -> `runAction` -> toast + close on `ok`, inline message on failure; Speak button (Placeholder when unsupported, disabled when denied); `data-spatial="skip"` so the shell d-pad hook stays out.
- **Hub**: Commands + Speak buttons in the header (44 px, visible - nothing keyboard-only), actions `hub.openCommands` ("open the command palette") and `hub.voiceListen` ("listen for a voice command"). **TopBar**: Commands icon button labelled "Commands · Ctrl/Cmd + K".
- **DesktopShell**: `useSpatialNav(root, { onBack: drawer ? close : default })` + `useGamepadNav` on the shell root. **`useSpatialNav`**: arrow ownership is now per axis (`consumesArrows(el, dir)`: Up / Down leave a `Tabs` tablist, a `SegmentedControl` radiogroup or a single-line text field - the first rehearsal showed those as d-pad traps on S-03, S-05, A-01, D-06, D-09); Escape inside a select / text field parks focus and the next arrow resumes from that spot; **`inOpenDialog`** now ignores a closed `<dialog>` (the `Modal` always keeps one in the DOM, which would have made the hook inert on every page with a Modal - including every page now that the palette is global).
- **`npm run qa:dpad`** (`scripts/qa-dpad.mjs`): every built route at 1920 (16:9), super admin, dev mode off; breadth-first arrow-only walk from nothing focused, per route: reachable / candidates, primary CTAs never reached, dead ends vs arrow-owning controls, Backspace behaviour, "NO HOOK" pages; `docs/qa/dpad-report.{md,json}`; reuses a server on `--port`, else `vite preview` when `dist/` exists, else the dev server. First full run (dev server, 51 routes): see `docs/qa/dpad-report.md` - summary in "Kanban moves" below.
- Verified headless (Playwright, dev server :5199, 23 checks): 144 tools = 144 vocabulary entries; both hub actions live on the hub; Commands and Speak buttons >= 44 px; ArrowDown from nothing still focuses on the hub with the closed palette dialog in the DOM; Ctrl+K opens and focuses the input; empty query lists the 8 live hub actions; arrows inside the palette stay inside; "switch to dark mode" -> Theme -> Enter toggled light -> dark, toasted and closed; "set T45 to doing" prefilled `task = T45`, `status = doing`; Esc closes; `runAction('hub.voiceListen')` from the console opened the palette without listening; on `/studio` ArrowDown -> Commands, ArrowRight -> EN, Escape in a select parks and ArrowDown continues to the first prospect link; TopBar Commands opens the palette; zero page errors. `npm run typecheck` clean for this worker's files (`src/modules/admin/AbReadout.tsx` has three errors from the admin worker's in-progress pass, not touched here); `npm run test:engine` 20 / 20; `npm run test:voice` 18 / 18.

## New and changed contracts
- `src/a11y`: `matchPhrase(phrase, vocabulary, { lang?: 'en' | 'es', page?: string, route?: string, live?: (action) => boolean, limit? = 8, threshold? = 0.45 }) => Match[]` with `Match = { entry, action, score, params: Record<string, string | number>, missing: string[], sources: Record<string, 'phrase' | 'quoted' | 'route'>, phraseFilled, onPage, live, coverage }`; `fillPhrase(intent, params)`, `normalize`, `strip` (case kept), `canonicalize`, `routeIds`, `quoted`, `dice`. `useVoice({ lang, onResult(transcript, final), onError?(code) }) => { state, supported, start(): boolean, stop(), transcript, error }`; `voiceSupported()`.
- `useSpatialNav(ref, { enabled?, onBack? }) => { move(dir): boolean, activate(): boolean, back(): boolean, rootRef }` unchanged in shape; new behaviour: per-axis arrow ownership (`consumesArrows(el, dir?)` in `spatial.ts` gained the optional `dir`), Escape inside an arrow-owning control parks focus. **Landing pages** call it exactly as the hub does: `const root = useRef<HTMLDivElement>(null); const spatial = useSpatialNav(root, { onBack? }); useGamepadNav(spatial);` + `ref={root}` on the page root; regions that own arrow keys (the RoleViews strip) carry `data-spatial="skip"`.
- `src/actions/palette.ts`: `openPalette({ query?, voice? })`, `closePalette()`, `togglePalette()`, `paletteOpen()`, `usePaletteState() => { open, query, voice, seq }`, `isPaletteShortcut(e)`.
- New actions: `hub.openCommands` (any role), `hub.voiceListen` (any role); handlers return `{ ok: true, open: true }` / `{ ok: true, open: true, voice: true }`.
- `control.*` string keys (hub table): `title, open, shortcut, placeholder, speak, listening, stop, heard, unsupported, denied, gesture, on_page, matches, no_match, needs, any_role, live, opens, params, optional, run, running, result_ok, result_fail, hint_keys, hidden_for_role` - all with `es`.
- npm: `test:voice` (esbuild bundle of `src/a11y/voice.ts` + the exported vocabulary, no browser), `qa:dpad [--only= --codes= --width= --port= --server= --max-steps= --strict]`.
