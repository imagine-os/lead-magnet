# L-02 · Savings audit landing

## Purpose

The archetype for cold, price-sensitive owners. It opens with the money - "<Business> is paying about $X a month for tools that do not talk to each other" - and then hands the number back: every tool we guessed is a row with Yes / No buttons, and the savings counter beside it moves as they answer. A number they can correct beats a number they must believe, and each correction is a real write that sharpens their profile for the studio.

## Logic

- `booking_inline` renders `previewSlots(slotGrid(prospect.id, tzForProspect(prospect)))` from `src/engine/slots.ts`: three free slots per open day in the prospect's timezone, every one of them a real B-01 slot; picking one deep-links `/book/:id?slot=<ISO>` (D-051). The page opens in `prospects.lang` unless the viewer chose EN / ES (D-034).

- Rows come from the live `stack_guesses` table (the model's snapshot is only a fallback), so the audit, the savings stack, the studio and the analytics all read the same corrected list.
- An answer calls `update('stack_guesses', id, { status })` and emits `form_submit { form: 'stack_audit', tool, answer, monthly_cost }`.
- `savings(prospect, rows)` recomputes on every change: rejected rows drop out of `items`, `tools_cut`, `monthly_current` and the net annual figure.
- Nothing on this page asks for an email; the audit is the value exchange (R-C01).

## Real vs mock

Real: the corrections, the recomputation, the events. Mocked: the prices themselves are catalog estimates scaled by seats and locations - the page says so in the section subline and in the note beside the counter.
