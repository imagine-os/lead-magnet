# S-03 · Page composer

## Purpose

Choose the landing archetype with the scoring in front of you, see the real public route at phone and desktop width, and publish a workspace that lives 14 days. A slug can carry **two live pages at once - variant A and variant B** - each with its own archetype, its own `PageModel` snapshot, its own expiry and a link that forces it (`#/p/<slug>?variant=B`). Publishing snapshots a `PageModel` into `pages.model`, so the landing page renders what was composed and never recomputes.

## Rules

- `R-S01` - publish is blocked under confidence 0.3 unless the override toggle is on
- `R-S02` - `published_at = now`, `expires_at = now + 14 days` (`PAGE_TTL_DAYS`)
- `R-C05` - the same 14 days the CTA band promises; expired pages fall to L-05
- `R-S04` - a slug carries at most two live rows (A and B); anything that needs "the" page takes A
- `R-E02` - the ranking is the playbook scoring
- `R-S03` - insert then update by id; no page state lives only in memory

## Logic

- Archetype: the picked one, else the selected variant's current one, else the top-ranked one.
- Variants: `variantRows(pages, prospectId, slug)` returns A and B (row or null). Publishing variant X updates X's row when it exists and inserts one otherwise, always with a freshly composed model for that row's id - so the two snapshots are independent.
- Forced links put the query inside the hash (`#/p/<slug>?variant=B`) because the app is a HashRouter; the landing module splits sessions between the live rows and honours the query.
- Slug: the existing page's slug wins so a published link never moves; otherwise `slugify(business-city)`.
- Publish with an existing row: one `update` with the recomposed model. First publish: `insert` (model null) then `update` with `composePage(p, archetype, { pageId: created.id, ... })`, because the snapshot carries its own page id.
- Expire sets `status: expired` and keeps the snapshot so analytics and page docs still resolve.
- Preview routes: `reveal -> /p/:slug`, `audit -> /p/:slug/audit`, `walkthrough -> /p/:slug/story`, `letter -> /p/:slug/letter` (owned by the landing module).
