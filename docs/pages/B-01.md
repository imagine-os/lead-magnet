# B-01 · Book a call

## Purpose

The prospect picks a 15-minute walkthrough of the system we already built for them, in their own timezone, and only then gives a name and email. It is a public page with its own slim chrome, themed to their palette through `--lp-*`, and it is the last step of the funnel before a human call. The calendar is never behind a form (R-C01 / R-B01).

## Sections (layout order)

1. Slim top bar - business wordmark (links to their landing page), timezone abbreviation, `LangToggle`
2. Head - 15-minute badge, headline with their first name, what the call is
3. **1 · Choose a time** - next 7 days of 15-minute slots; day `Chip`s under 900 px, all seven day columns above it
4. **2 · Where do we send the link?** - name (required), email (required), phone (optional), note; inert until a slot is picked
5. Confirm + "Open your demo" secondary
6. Dev-mode note: the calendar is mocked, the provider lands in T42

## Data

| Table | Read / write | Notes |
| --- | --- | --- |
| `prospects` | read | by route id; city / country -> timezone, style -> theme |
| `pages` | read | the live page supplies `page_id` for tracking and the wordmark link |
| `bookings` | write (insert) | one row per confirm: `status: requested`, `duration_min: 15`, `contact_name`, `contact_email`, `contact_phone` (null when empty), `notes` = the free-text note |
| `events` | write | `booking_started` once per session on the first pick, `booking_confirmed` on confirm |

## Rules

- `R-B01` - the details fieldset is `disabled` and says "Pick a time above and this opens up" until a slot exists
- `R-B02` - 15-minute steps, `duration_min: 15` on the row
- `R-B03` - the booking is inserted through the provider and read back by id on B-02
- `R-C01` - nothing is gated behind the form; the demo link sits beside Confirm
- `R-C06` - both booking events go through `track()`

## Logic

- Timezone: `prospects.city` -> IANA zone (`CITY_TZ`, then country, then `America/New_York`). Wall-clock -> instant uses a two-pass `Intl` offset, so DST is correct without a date library.
- Grid: next 7 days from tomorrow, 09:00-17:00 local, 15-minute steps, 12:00 hour blocked for lunch, Saturday and Sunday closed.
- Availability: `FNV-1a(prospectId | day | hh:mm) % 100 < 42`. Identical on every machine and every render; if a working day would come out empty, 10:00 and 14:00 are opened.
- `?slot=<iso>` (from the landing page's inline calendar) preselects any valid instant. If the generated grid lacks it (different minute, closed day, outside the window) or generated it as busy, `withRequested()` appends / frees it in its day marked **requested** (dashed outline + label), never silently swapping another time. The day containing it is selected.
- Grid, timezone and words come from `src/engine/slots.ts` (pure, unit-checked), the same module the landing preview and A-05 use, so the slot a prospect picked on the landing page exists here.
- Validation: name non-empty, email matches a single-`@` pattern; errors appear on submit, not while typing.

## Real vs mock

Real: the `bookings` row, the two events, the timezone maths, the theming, EN/ES. Mock: availability (deterministic hash). Not wired: the booking provider (T42) - a dev-mode note says so and the flow works end to end without it. When Supabase lands (T44) the insert is unchanged; only the provider behind `useData()` changes.
