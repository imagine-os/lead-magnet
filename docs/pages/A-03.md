# A-03 · Events log

## Purpose

The raw tracking table. This is where you prove that a page tracked what it claims: filter by type, page, session or prospect, then open any row's full `meta` JSON.

## Sections (layout order)

1. Filters - type, page, session, prospect (four `Select`s) + clear + "{shown} of {all} events"
2. `DataTable` - when, type (with icon), prospect link, page + variant, session id, meta summary, Raw button
3. `Drawer` - id, timestamp, session, page, prospect and the pretty-printed `meta`

## Data

| Table | Read / write | Notes |
| --- | --- | --- |
| `events` | read | newest first by `ts` |
| `pages` | read | page filter options and the slug / variant column |
| `prospects` | read | prospect filter options and the link |

## Actions

| id | intent | permission |
| --- | --- | --- |
| `admin.filterEvents` | "show {type} events for {prospect}" | `events.read` |
| `admin.clearEventFilters` | "clear the event filters" | `events.read` |
| `admin.openEventMeta` | "show the meta for event {id}" | `events.read` |

## Rules

- `R-A01` - event labels match the funnel vocabulary
- `R-C06` - every row here came from `track()`

## Logic

- Filters are AND-combined; an empty value means "all".
- Session options are derived from the rows, so a brand-new visitor shows up without a schema change.
- The row click and the Raw button both open the same drawer (nothing is hover-only).
- `eventSummary()` renders a compact line from known meta keys and falls back to the first two keys, so no meta is invisible in the table.

## Components

`DataTable`, `Drawer`, `Select`, `Field`, `Badge`, `Button`, `Card`, `Icon`.

## Real vs mock

All real rows. Seed traffic is fictional but written through the same path as live traffic.

## Responsive check (P-01)

Declared at 360, 390, 768, 1280, 1920, 2560, 3840. Filters are an auto-fit grid (one column on a phone); `DataTable` switches to cards and the Raw column is `hideOnCard` because the whole card is clickable there. `Drawer` is full-height with a 520 px panel.
