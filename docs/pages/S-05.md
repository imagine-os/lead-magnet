# S-05 · Outreach composer

## Purpose

The message that points at the page. Two or three templates per channel, written in English and Spanish, with the prospect's tokens already filled from the profile, the savings and the live page URL. Draft lands in `touches`; sending is not wired, so the honest demo path is "mark as sent".

## Screenshots

Not captured yet - `npm run screenshots -- --codes=S-05` in the screenshot pass (T31).

## Sections (layout order)

1. Prospect nav
2. Header - channel select, EN / ES picker, token legend, "no live page" warning
3. Templates - the channel's templates as cards with the filled subject line
4. Message - subject and body, editable, reset to template
5. Preview - the message as it will read, with the public URL
6. Touch history - every touch for this prospect with status and "mark as sent"

## Data

| Table | Read / write | Notes |
| --- | --- | --- |
| `touches` | read / write | insert on draft, update on mark-as-sent |
| `prospects` | read | tokens |

| id | intent | permission |
| --- | --- | --- |
| `studio.pickChannel` | "write a {channel} message" | any |
| `studio.pickTemplate` | "use the {template} template" | any |
| `studio.draftTouch` | "draft a {channel} message" | `prospects.write` |
| `studio.sendTouch` | "send the message" | any (Placeholder) |
| `studio.markTouchSent` | "mark {touch} as sent" | `prospects.write` |

## Rules

- `R-S03` - draft is an insert, mark-as-sent is `update('touches', id, patch)`
- `R-C06` - outreach opens and clicks arrive as `events` from the landing side; the touch row is what they join to

## Logic

- Channels: cold email, LinkedIn DM, WhatsApp, SMS, call script, warm intro. The default channel follows `prospects.source`.
- Tokens: `{first_name} {last_name} {business} {city} {industry} {savings_annual} {savings_monthly} {tools_cut} {page_url}`. An unknown token is left visible on purpose so nothing half-written goes out.
- Message language defaults to `prospects.lang` and can be switched per message without touching the profile.
- Drafting stores the first 280 characters as `body_preview` (the column the admin board reads) and links the live page id.

## Components

Select, SegmentedControl, Textarea, Input, Field, Card, DataTable, Badge, Button, Placeholder, EmptyState.

## Real vs mock

Real: templates, token filling, drafts, history, status changes. Mocked: sending - no email, DM, WhatsApp or SMS provider is wired; "mark as sent" is explicitly a demo action and says so in its toast.

## Responsive check (P-01)

Checked at 360, 390, 768, 1280, 1920, 2560, 3840 - no horizontal overflow; the composer and preview stack under 1100 px and the history table becomes cards under 768.
