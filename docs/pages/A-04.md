# A-04 · Outreach board

## Purpose

Every outreach touch as a card in a status column, so you can see where the cold list is stuck. Moving a card is a `Select`, never a drag: it works on a keyboard, a phone, a pen and later a remote (P-03, P-04).

## Sections (layout order)

1. Channel filter + "{shown} of {all} touches"
2. Board - `draft`, `sent`, `opened`, `clicked`, `replied`, `other`; each column headed with its count
3. Touch card - channel with icon, warmth, subject, body preview, prospect and page links, timestamps, "Move to" `Select`

## Data

| Table | Read / write | Notes |
| --- | --- | --- |
| `touches` | read / write | `status` plus the timestamps that status implies |
| `prospects` | read | name, warmth |
| `pages` | read | the page a touch points at |

## Actions

| id | intent | permission |
| --- | --- | --- |
| `admin.moveTouch` | "mark {touch} as {status}" | `prospects.write` |
| `admin.filterOutreach` | "show only {channel} outreach" | `events.read` |

## Rules

- `R-A01` - outreach statuses are the source of the `outreach_open` stage upstream
- `R-P01` - the Select is disabled through `can('prospects.write')`, never a role comparison

## Logic

- `scheduled` and `bounced` are collected in an **other** column, so no touch can vanish from the board.
- Moving forward stamps `sent_at` / `opened_at` / `clicked_at` when they are missing and never clears an earlier stamp; moving back to `draft` only changes the status.
- Writes go through the provider by id; the board re-renders from the change event (P-14).

## Components

`Card`, `Select`, `Field`, `Badge`, `Icon`, `EmptyState`.

## Real vs mock

Real: the rows, the statuses, the timestamps, the permission gate. Not wired: actually sending a message - S-05 drafts it and a provider sends it (T41). The page says so in a footnote.

## Responsive check (P-01)

Declared at 360, 390, 768, 1280, 1920, 2560, 3840. Above 900 px the board is one horizontal strip of `minmax(280px, 1fr)` columns with sticky column heads; under 900 px it becomes stacked sections with no nested scrolling. Column width steps to 320 px at 1920 and 380 px at 2560.
