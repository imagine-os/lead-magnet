# 0002 - plan (T10): Plan viewer: Kanban, list, dependency graph, task detail

version: 0.2.0 (shipped in the 0.2.0 integration pass; module work dated 2026-09-18)
date: 2026-09-18
prompt: 0001
intent: The first deliverable Justin asked for - a PM viewer over the development plan (Kanban, list, timeline with dependencies) where tasks are bound by dependencies, not calendar days, and every task names the model that does it.
decision: (1) the timeline is a dependency graph with phase columns and no date axis, and its one length metric is the critical path (longest dependency chain), not a duration; (2) R-K01 is enforced on the write, not only shown - a task cannot be set to done while a dependency is open, and blocked / awaiting_justin stay always-allowed so a human blocker can be recorded honestly; (3) same-phase dependencies get their own sub-column so every arrow points right and the graph stays readable without a layout library; (4) plan actions call through a `useLatest` ref because `useActions` registers once per page code, so WebMCP / voice callers see current data; (5) only `status` (+ `done_at`) is editable from the product - the plan's shape stays authored in `docs/build-plan.md` / `src/data/seed/plan.ts`.
rejected: a Gantt / calendar timeline (calendar days are exactly what the plan is not bound by); a drag-and-drop Kanban as the only move affordance (P-03: nothing drag-only; a Select plus prev / next lane buttons is keyboard, touch, pen and remote friendly, and drag can be added later on top of them); d3 / dagre / react-flow for the graph layout (a new dependency needs a decision row, and phase columns plus a topological order are ~40 lines of pure TypeScript we can test); editing titles, notes and dependencies in the UI (two sources of truth against the docs); computing a projected finish date from task counts (invented precision).

## What changed

- **K-01 `/plan`** - five lanes (backlog, doing, done, blocked, awaiting Justin) from `TASK_STATUS`. Cards show the id (link to K-04), model badge, phase, title, module, code chips, `{done}/{total} deps done` with a tooltip naming what is still open, and a ready badge. Moving a card writes `tasks.status` (and `done_at`) by id through `useData().update`; the controls are a status `Select` plus prev / next lane `IconButton`s - there is no drag, so nothing is drag-only. Filters: phase, model, "ready only". Counts + progress bar. `Sync to build-plan.md` is a `Placeholder` (T20). Without `plan.edit` (analyst) the page is read-only and says so.
- **K-02 `/plan/list`** - `DataTable` of all 31 tasks: id, title, module, codes, model, phase, depends on (linked ids, green when that dependency is done), status (+ ready), owner. Sortable on every column (numeric columns compare numerically), filters by status / model / phase, row click and first-cell link open K-04.
- **K-03 `/plan/timeline`** - the dependency graph as inline SVG. Phases 0..4 are column bands, tasks are nodes in topological order, `depends_on` are arrowed edges. Node colour by status, model printed in the node, ready dot. Click / Enter / Space on a node (or the focus Select, or `?focus=<id>`) lights the focused task plus everything transitively upstream (dashed) and downstream (accent) and dims the rest; a side Card shows the details and both dependency directions. Legend, zoom buttons + `+` / `-` / `0` keys, Escape clears. Critical path count with the chain in the hint (8 today: T01 -> T02 -> T04 -> T06 -> T10 -> T20 -> T45 -> T46). The graph scrolls horizontally inside its own frame only; the page never scrolls sideways. Title line: "Tasks are bound by dependencies, not calendar days."
- **K-04 `/plan/tasks/:id`** - header, badges, status `Select` with the R-K01 hint, facts (`module`, `owner`, `model`, `phase`, `codes`, `done_at`, `updated_at`), notes, rule links, "waits on" (upstream) and "blocks" (dependents) both linked with their status and model, "see it in the graph" (deep-links K-03 with the focus set). Unknown id renders an `EmptyState`, not a blank page.
- **`src/rules/plan.ts`** - R-K01 (nothing done while a dependency is open), R-K02 (every task names its model), R-K03 (the status vocabulary is exactly five lanes), R-K04 (ready = all dependencies done; `done_at` stamped / cleared with the status). All four show at `/#/dev/rules`.
- **`src/modules/plan/taskModel.ts`** - pure helpers: `readiness`, `dependentsOf`, `topoOrder`, `criticalPath`, `upstreamOf` / `downstreamOf`, `statusChange` (the R-K01 gate), `statusPatch`, `buildGraph` (phase columns + same-phase sub-columns), `edgePath`. Smoke-checked against the 31 seeded tasks: 31 nodes, 42 edges, 9 columns, no backward edges, no overlapping nodes, critical path 8, 7 tasks ready.
- Strings: 90+ keys under `plan.*`, EN + ES filled in this pass (no hard-coded English in JSX).
- No component was edited and no shared file was touched; the module registers the same four paths as the stubs, so the registry swaps stub -> built with no change to `registry.ts`.

## Requests to foundation

1. **`DataTable` sortable headers.** `Column<T>.header` is a `string`, so a header cell cannot be a sort button. K-02 puts the sort controls in a toolbar above the table and marks the active column with an arrow in the header text. Please add `headerNode?: ReactNode` (or `sortable?: boolean` + `sortDir` + `onSort`) so the `<th>` can hold the button with `aria-sort`. Every list page will want it.
2. **`useActions` stale closures.** `useActions(pageCode, map)` registers with deps `[pageCode]`, so handlers capture the first render's state. Every plan action goes through a local `useLatest` ref to work around it. Either re-register when the map identity changes, or ship a `useLatestActions` helper in `src/actions` so each module does not reinvent it (D-008 calls the manifest the WebMCP surface, so handlers reading stale data is a correctness problem, not a nit).
3. **`Badge` tone for a fifth hue.** `MODEL_TONE` maps the four models onto `primary` / `accent` / `info` / `warn`. If a fifth model appears, the tones run out before the vocabulary does - a `tone="ink"` variant already exists, so this is a note, not a blocker.
4. **Screenshots** for K-01..K-04 at 390 / 1280 light + dark are referenced by the page docs and are owed by T31.
