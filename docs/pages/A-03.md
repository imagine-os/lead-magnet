# A-03 · Events log

## Purpose

The raw tracking table. This is where you prove that a page tracked what it claims: filter by type, page, A/B variant, session or prospect, then open any row's full `meta` JSON.

## Rules

- `R-A01` - event labels match the funnel vocabulary
- `R-A02` - the variant shown is the one the row really belongs to; nothing is inferred beyond `pages.variant` / `meta.variant`
- `R-C06` - every row here came from `track()`

## Logic

- Filters are AND-combined; an empty value means "all".
- Session options are derived from the rows, so a brand-new visitor shows up without a schema change.
- The row click and the Raw button both open the same drawer (nothing is hover-only).
- `eventSummary()` renders a compact line from known meta keys and falls back to the first two keys, so no meta is invisible in the table.
- **Variant** (`variantOfEvent()` in `src/modules/admin/ab.ts`): the `pages` row the event points at decides the side; if the page row is gone, the `variant` the landing page stamped into `meta` is used; otherwise the row is "no page" and the A / B filter excludes it. Nothing is invented - `track()` records `page_id`, `prospect_id`, `session_id`, `type`, `meta` and `ts`, and the landing module stamps `{ variant, page_id, archetype, slug }` into `meta` on every event it fires.
