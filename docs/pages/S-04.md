# S-04 · Assets & image prompts

## Purpose

Every image and video prompt the prospect's page needs - hero, three device mockups, one card per role, the social preview and the video frame sequence - already carrying their palette, tone and industry motifs. Edit a prompt before it is ever sent, and approve or reject what comes back. The image provider is not wired (T40), so Generate is a `Placeholder`, never a fake.

## Data

| Table | Read / write | Notes |
| --- | --- | --- |
| `assets` | read / write | prompt text and status by id; rows inserted on first visit |
| `prospects` | read | `imagePrompts(p)` is the source of truth for prompts, aspects and notes |

## Actions

| id | intent | permission |
| --- | --- | --- |
| `studio.generateAsset` | "generate the {kind} image" | any (Placeholder) |
| `studio.savePrompt` | "save the prompt for {asset}" | `prospects.write` |
| `studio.approveAsset` | "approve {asset}" | `prospects.write` |
| `studio.rejectAsset` | "reject {asset}" | `prospects.write` |

## Rules

- `R-S03` - prompt edits and status changes are `update('assets', id, patch)`
- `R-P02` - Generate is a Placeholder: tooltip on hover and focus, toast on activation, dashed badge in dev mode

## Logic

- First visit for a prospect with no assets: the `imagePrompts()` list is materialised as `queued` rows (guarded by a ref so it happens once).
- Aspect and notes come from the engine prompt matched by text, so an edited prompt simply loses its hint rather than breaking.
- A prompt saves on blur, only when it actually changed.
